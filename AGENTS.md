# mnemonic

Collects agent session traces (Claude Code, Codex, Cursor, ...) from every machine, keeps them on one server, and serves them to agents over MCP from DuckDB. Replaced a ClickHouse-backed predecessor (see NOTICE), for personal and team use.

## Shape
- `mnemonic push` on each machine (launchd, every 60 s) sends **redacted raw lines** to the server. It is pure Go, built with `CGO_ENABLED=0`, and has no parser or DuckDB in it.
- `mnemonic serve` on the server:
  - accepts pushes (`/v1/*`);
  - re-parses whole raw files into `events` parquet (`internal/lake`);
  - rebuilds `cache-<ms>.duckdb` (`internal/cache`);
  - answers MCP on `POST /mcp` (`internal/mcp`, `internal/query`).
- Raw is the source of truth, and parquet and the cache are derived. A parser fix is a redeploy plus a re-parse.
- Paths live in `internal/layout`. The push protocol is `internal/wire`. Auth (bearer token → author) is `internal/auth`; the author is never taken from a request.

## Contracts (change only with the owner)
| Contract | File | Pinned by |
|---|---|---|
| Event columns | `internal/schema/events.go`, generated by `go run ./scripts/genschema` from `docs/clickhouse/events.tsv` | regenerate; never hand-edit |
| Parser output | upstream `ingest-core/src/sources/*` | `internal/normalize/all/golden_test.go` against `testdata/goldens` |
| Cache relations | `internal/cache/schema.sql` | the query tests |
| MCP tool surface | `internal/mcp/tools.json` (dumped from the upstream MCP 0.7.3 `tools/list`) | served verbatim |
| Prose output | upstream `mcp-core/src/*_v1.rs` | their unit tests, ported with literal strings |

The upstream project (URL in NOTICE) is the `upstream` git remote. Read it with `git show upstream/main:<path>`.

## Gates (every change)
```
gofmt -l . | grep . && exit 1
go vet ./...
CGO_ENABLED=0 go build -o /dev/null ./cmd/mnemonic
go build -tags server -o /dev/null ./cmd/mnemonic
go test ./internal/<your package>/...
```

## Rules
- **The owner's machine is not a load box.** Never run push, lake or cache over the real corpus locally. Use `go test -p 2`, at most 3 `go test` processes across lanes, and no Docker. Corpus runs happen on the server.
- **Tests.** One golden or table test per package that asserts literal values. No test that would pass if the code returned nothing. Scratch tests are `*_scratch_test.go`, which git ignores.
- **Lane ownership.** A lane edits only the files its packet names. A stub that says `panic("lane X")` belongs to lane X.
- **Commits.** No commit trailers. Work lands on `main`. Lane branches are `lane/<name>`, pushed, and deleted after merge.
